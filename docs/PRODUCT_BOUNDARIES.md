# 产品边界：模拟 vs 真实

这个项目最容易被改坏的地方是：**把模拟数据做得太像真的，让使用者（和 Agent 自己）误以为能力已经接通**。这份文件是判定规则。

## 一句话规则

凡涉及**执行、评分、外部调用**的 UI，在没有真实后端支撑时，必须显示"模拟/演示"标识；不允许混合真实与模拟数据却不说明来源。

## 模块状态表

| 模块 | 状态 | 说明 |
|---|---|---|
| 要件定义表单 | 已实现 | 真实本地行为，数据存浏览器 localStorage |
| 编排画布（拖拽、连线、版本快照） | 已实现 | 真实本地行为 |
| 成员脚手架配置 | 已实现 | 真实本地行为；模型参数按所选模型能力显示 |
| 配置检查（检查配置按钮） | 已实现 | 真实本地静态分析，非模拟 |
| 资源库 | 已实现 | 本地目录管理 |
| 本地备份（JSON 导出/恢复） | 已实现 | 真实本地行为 |
| 试运行播放 | 模拟中 | 预置轨迹的模拟播放器；自定义输入/改动配置后不会得到预置版本的质量成绩 |
| Trace 详情 | 模拟中 | 展示演示数据；结构按真实 OTLP 接入方向设计 |
| Code/LLM 评价 | 模拟中 | 机器评分为演示数据；人工批注是真实本地保存 |
| 回归用例与版本比较 | 模拟中 | 数据集与比较结果为演示数据；本地扩展用例集为真实本地行为 |
| 执行引擎 | 未接入 | 不存在真实 Agent 执行 |
| OTLP / OpenTelemetry | 未接入 | 仅数据模型方向预留 |
| 批量评测执行器 | 未接入 | 预留 Promptfoo/自定义执行器接口位置，UI 显示未接入 |

状态只有三种：**已实现**（真实本地行为）、**模拟中**（演示数据，界面必须有标识）、**未接入**（UI 明确显示未接通，不假装可用）。

## 混合态规则

- **真实配置驱动模拟播放**：用户编辑的真实配置作为快照驱动一次模拟播放，属于"真实输入 → 模拟输出"。输出侧必须整体标注为模拟，不得因为输入是真实配置就省略标识。
- **混合面板双侧标注**：人工批注（真实本地保存）与 Code/LLM 评分（模拟）出现在同一面板时，两侧都要各自标注来源，不允许只标模拟侧。
- **导出数据的标识延续**：通过"本地备份"导出的 JSON 自含 `synthetic: true` 等来源字段；任何读取导出文件的外部工具都应保留这些字段。
- **标识粒度**：页面级"模拟数据"标识在当前纯模拟阶段可以覆盖整页；出现任何一条真实执行/评分数据后，必须改为按行/按条目标注（数据模型已预留 `synthetic` / `model_called` / `provenance` 字段）。

## 接入真实引擎前必须升级的规则

- 状态表从"模块 → 单状态"升级为"模块 × 子能力（执行/采集/评分/存储）→ 状态"，以表达"真实执行 + 模拟评分"等组合态。
- 运行记录、Trace、比较页的标识从页面级常量改为行级字段驱动。
- 恢复逻辑中 `running → cancelled` 是模拟假设（真实后台任务不会因页面关闭而取消），接入时必须区分。

## 标注约定

- 模拟数据在界面上必须有可见的"模拟/演示"标识，不能只在代码注释里说明。
- 新增涉及执行/评分的 UI 时，默认按"未接入"或"模拟中"处理，并在本表登记。
- 任何模块从"模拟中"升级为"已实现"（接真实后端）时，必须同步更新本表和 README 的"边界"一节。

## 为什么不现在接真实后端

先在模拟数据上把"定义 → 运行 → 定位 → 评估 → 修复 → 验证"的闭环走通，确认交互和数据模型是对的，再接真实引擎。接入前提见 `ROADMAP.md` 第三节。顺序反了会变成：后端改一次、UI 推翻一次。
